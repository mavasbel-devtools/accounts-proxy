# accounts-proxy providers reference

One section per provider: how it signs in, where its credentials are kept, how they renew, which formats and upstream
endpoints it serves natively, what it changes in a request and an answer, its model list and quota, and what the live
measurements found. Kept current in place (plan 2026-10-16 decision D3). Related references:
[API](2026-10-17-19-26-proxy-api.md) · [format fields](2026-10-17-19-26-format-fields.md) (the field-by-field rules
per cell) · [models](2026-10-17-19-26-models.md) · [client setup](2026-10-17-19-26-client-setup.md).

Overview:

| Provider | Kind | Sign-in | Native formats | Upstream |
|---|---|---|---|---|
| [`claude`](#claude) | subscription (Claude Pro/Max) | browser OAuth (`--manual`: paste code) | Anthropic Messages | `api.anthropic.com` |
| [`antigravity`](#antigravity) | subscription (Google Antigravity) | browser OAuth | Gemini | `daily-cloudcode-pa.googleapis.com` (Cloud Code Assist envelope) |
| [`openai`](#openai) | subscription (ChatGPT plan usage) | browser, Sign in with ChatGPT | OpenAI Responses | `api.openai.com/v1` |
| [`openrouter`](#openrouter) | API-key gateway | browser PKCE yielding a key (`--manual`, `--key`, `--from-opencode`) | Messages, Chat, Responses for every model | `openrouter.ai/api/v1` |
| [`opencode`](#opencode) | API-key gateway (OpenCode Zen) | OpenCode Console device login (`--key`, `--from-opencode`) | per model: Messages, Chat, Responses, Gemini | `opencode.ai/inference` |
| [`opencode-go`](#opencode-go) | API-key gateway (OpenCode Go) | the `opencode` account | per model: Messages, Chat, Responses, Gemini | `opencode.ai/inference/go` |
| [`cheaper-inference`](#cheaper-inference) | API-key gateway | API key at a hidden prompt (`--from-opencode`) | per model: Messages (+ `count_tokens`), Chat, Responses | `api.cheaperinference.com/v1` |

Common to every provider:

- **Opt-in.** A provider starts only with `providers.<id>.enabled: true` in `proxy.yaml`; the three subscription
  providers also need `acknowledgeTermsRisk: true`, because their terms restrict third-party clients
  ([research](../research/2026-10-05-20-07-llm-router-from-auth-plugins.md) §3,
  [OpenAI rules](2026-10-11-23-08-openai-chatgpt-plan-rules.md)).
- **Own credentials.** Accounts live only in `<data>/accounts-<provider>.json` (0600), written by a locked
  read-change-write; `account use` picks the active one and the proxy never switches accounts by itself, also not on
  a 429.
- **Renewal** (renewing providers: `claude`, `antigravity`, `openai`, the `opencode` Console sign-in): the access token
  is renewed 2 minutes before it expires, once for all concurrent requests and processes, under the renewal lock; each
  token call is bounded by 30 s; a transient failure keeps a still-valid token and retries after 30 s; a rejected
  refresh marks the account `needs login` and requests answer 401 `provider_auth_required` without calling the token
  endpoint until `login` ([AGENTS.md](../../AGENTS.md) §4 Sessions). API keys never renew; an upstream 401 on a key
  reaches the client unchanged.
- **Answers.** On a native cell the provider's status and body reach the client as they arrive, plus the response
  headers listed per provider. Upstream errors keep their status, body and `retry-after`.

## claude

| | |
|---|---|
| Sign-in | `login claude`: the browser opens `https://claude.com/cai/oauth/authorize` (PKCE S256); a listener on `127.0.0.1` answers the redirect `http://localhost:<port>/callback`; the code is exchanged at `https://platform.claude.com/v1/oauth/token` ([P0-E6](2026-10-06-00-32-p0-e6-browser-login-mechanisms.md)). `--manual`: the printed page shows a code to paste |
| Credentials | `accounts-claude.json`; several accounts, one active |
| Renewal | the refresh token rotates on every renewal and the old one is then rejected (live E4, [record](2026-10-11-23-06-e4-refresh-rotation.md)): a login shared with Claude Code or the plugins would break one of them, so the proxy keeps its own. An upstream 401 renews the token once and resends the request, only before anything reached the client (plan v4 H-d) |
| Native routes | `POST /anthropic/v1/messages` → `/v1/messages?beta=true`; `POST /anthropic/v1/messages/count_tokens` → `/v1/messages/count_tokens?beta=true` (without the Messages-only envelope fields, F10); any other path 400 `invalid_request` |
| Request | the Claude Code request envelope of the source plugin (opencode-claude-auth @ 6292741): billing and identity system blocks, `metadata.user_id`, the model's captured `anthropic-beta` set, the never-prefill guard, the client's thinking honoured (decision Q6). Field by field: [format fields §1](2026-10-17-19-26-format-fields.md#1-claude--anthropic-messages) |
| Answer headers | `content-type`, `retry-after`, `request-id`, every `anthropic-ratelimit-*`, and `x-proxy-dropped` when something was dropped |
| Streaming | the upstream event stream is passed chunk by chunk (fix F1 of the source relay, which buffered) |
| Model list | `model_selector/cc` and `bootstrap` (Claude Code 2.1.304 flow) when organizationUuid is present; fallback to `GET /v1/models` (100 per page, up to 10 pages, 3 s per page); kept `modelListMaxAgeMinutes` (default 24 h); then the stored copy; then the built-in list of 10 (`STATIC_CATALOG`). Never empty |
| Quota | not reported (`quota claude` fails with "does not report usage") |
| Live findings | count_tokens refuses the Messages-only envelope fields as extra inputs (F10, [P6 probe](2026-10-18-18-39-p6-count-tokens-probe.md)); timing in [P6 results](2026-10-18-20-07-p6-live-results.md); thinking stays the client's: absent stays absent, `disabled` works, and the clear-thinking `context_management` edit goes only with thinking on ([P0-LIVE](2026-10-10-23-17-p0-live-findings.md) L1–L3, [Q6](2026-10-10-23-20-q6-thinking-probe.md)); stop sequences also match inside thinking text (L4); `cache_control` works (F9); opencode needs rule O6 for Claude 5.1+ ([catalog rules](2026-10-16-01-38-model-catalog-rules.md)) |
| Media | measured through the proxy ([M1 media probe](2026-10-24-21-05-m1-media-probe.md)): images and PDFs, inline (base64) and by `url` source, pass unchanged and are read (`claude-haiku-4-5-20251001`); the model lists name text, image and PDF only. The Files API is not served: `POST /anthropic/v1/files` answers 400 ("request body is not valid JSON": every other `/anthropic/v1` path is a Messages request), and a `file` source with `anthropic-beta: files-api-2025-04-14` is 400 `unsupported_feature`, that beta being outside the model's captured set |

## antigravity

| | |
|---|---|
| Sign-in | `login antigravity`: the browser opens `https://accounts.google.com/o/oauth2/v2/auth`; a listener on `127.0.0.1` answers `http://localhost:<port>/oauth-callback`; the code is exchanged at `https://oauth2.googleapis.com/token`; then the account's e-mail, project and model list are read. Google may show "this app isn't verified": the sign-in uses the Antigravity IDE's own client, as the source plugin does |
| Credentials | `accounts-antigravity.json` (Google tokens and the Cloud Code project) |
| Renewal | Google keeps the same refresh token on renewal (live E4). An upstream 401 renews once and retries, only before anything was yielded; a transient location (geo) gate is retried after 2 s and 8 s, only before the first byte |
| Native routes | `POST /gemini/v1beta/models/{model}:streamGenerateContent` (SSE with `?alt=sse`, else a JSON array written incrementally) and `:generateContent` (the stream merged into one answer, decision Q4), both through `v1internal:streamGenerateContent`; `:countTokens` 400 `unsupported_feature` (cloudcode-pa has no token-count endpoint) |
| Request | the public Gemini body checked against what the IDE sends and the live probes accepted, then wrapped in the Antigravity envelope with the trajectory labels, request id and the int64 `sessionId` kept as a decimal string; `thinkingBudget` is the catalog's; thought signatures are captured and replayed. Field by field: [format fields §2](2026-10-17-19-26-format-fields.md#2-antigravity--gemini) |
| Answer | `content-type` (set by the proxy: `text/event-stream` with `alt=sse`, else `application/json`) and `x-proxy-dropped`; each upstream envelope's `response` is the public `GenerateContentResponse`; a stream that fails after its first byte ends with a Google error frame |
| Errors | 429 → `quota_exhausted` with `retry-after`; another upstream status → `upstream_error` with that status, its Google envelope passed verbatim; a malformed or empty stream → 502 `upstream_error` |
| Model list | live `v1internal:fetchAvailableModels` only (no built-in list; without an account the provider is `unavailable`), minus the upstream's own tab and deprecated exclusions (IDE helper models such as `tab_*` that it does not exclude stay listed, L13); memoized per process, refetched once when a request names an unknown id |
| Quota | `quota antigravity`: remaining fraction and reset time per model group |
| Live findings | function-calling modes other than `AUTO`/`VALIDATED` are ignored by Gemini and GPT-OSS models and rejected by Claude models (L6), so the proxy refuses them; GPT-OSS reads no images, rejects PDFs and makes one tool call per turn; Gemini caches repeated prompts automatically (F9); `parametersJsonSchema` is accepted unchanged on Gemini and Claude models while the same schema as `parameters` is a 400 ([live validation F2](2026-10-13-02-52-live-validation-findings.md)) |
| Media | measured through the proxy ([M1 media probe](2026-10-24-21-05-m1-media-probe.md)): inline images, PDFs, audio (WAV) and video (WebM) are read by Gemini models (`gemini-3.5-flash-lite`); `fileData` by URL passes and the upstream fetches the file itself (a PDF URL and an image URL were read; an unreachable URL is the upstream's own 400); `responseModalities` `TEXT`/`IMAGE` returns an image (`gemini-3.1-flash-image`); `mediaResolution` `LOW`/`MEDIUM`/`HIGH` passes. Claude models on Antigravity (`claude-sonnet-5-5-low`) read images and PDFs, but a video answers the upstream's 500 "Unknown Error." although the model list names video. Audio output and other part keys stay refused ([format fields §2](2026-10-17-19-26-format-fields.md#2-antigravity--gemini)) |

## openai

| | |
|---|---|
| Sign-in | `login openai`: "Sign in with ChatGPT" for plan usage, OpenAI's documented flow for locally hosted apps ([rules](2026-10-11-23-08-openai-chatgpt-plan-rules.md)): `https://auth.openai.com/api/accounts/authorize` with `agent_name_hint=accounts-proxy` and a stable `ext_agent_host_id`; the redirect is `http://127.0.0.1:<port>/auth/callback` (never `localhost`); the first sign-in registers the app and OpenAI issues its own client id, kept per account; the ID token's signature and nonce are verified against OpenAI's JWKS. `--new` registers another ChatGPT account |
| Credentials | `accounts-openai.json` |
| Renewal | the refresh token rotates on every renewal (OpenAI documents reuse detection; live L2 rotated it) |
| Native route | `POST /openai/v1/responses` → `https://api.openai.com/v1/responses`; the opencode session headers `session-id`, `thread-id` and `x-client-request-id` are sent: the client's, else a session id the daemon draws once per process (`thread-id` and `x-client-request-id` default to the session id; decision O9). As opencode v2.1.1 sends it ([recon gap report §8](2026-10-21-20-44-recon-gap-report.md#8-openai-opencode-v211-chatgpt-sign-in)): the body zstd-compressed with `content-encoding: zstd` (P1); the client's `User-Agent` and OpenCode's own headers (`b3`, `traceparent`, `x-opencode-client`, `x-opencode-project`, `x-opencode-session`, `x-opencode-session-id`, `x-session-affinity`, `x-session-id`) forwarded as sent, the proxy's own `User-Agent` only when the client sends none (P2); no explicit `accept` (P3) |
| Request | `store: false` and `stream: true` always; a string `input` becomes one user message; the documented unsupported fields and hosted tools are 400 `unsupported_feature` or dropped with `x-proxy-lossy: 1`. Field by field: [format fields §3](2026-10-17-19-26-format-fields.md#3-openai--openai-responses) |
| Answer | streaming client: the upstream frames as they complete, the terminal `response` filled with the streamed items when it arrives with an empty `output` (rule I6); non-streaming client: one JSON response merged from the stream (decision O8), or the stream's failure as an OpenAI error with the documented status. Headers: `content-type` (plan usage sends none on its streams, so a streaming client gets `text/event-stream` from the proxy and a non-streaming one `application/json`; rule I7), `retry-after`, `x-oai-request-id` (plan usage's request id), `x-request-id` when present, and `x-proxy-dropped` |
| Model list | as opencode builds it for a ChatGPT sign-in: the reference catalog's `openai` models, in its order, whose id is one of opencode's 16 (`FALLBACK_MODELS`; 8 in the committed reference), with the reference's source; no model-list call to OpenAI, because opencode makes none (recon gap P4) |
| Quota | not reported |
| Live findings | the terminal `response.completed` carries `output: []` (rule I6, [live validation F1](2026-10-13-02-52-live-validation-findings.md)); the AI SDK sends `max_output_tokens`, which plan usage refuses, so opencode's manual setup needs `x-proxy-lossy: 1`; opencode's per-message effort updates are switched off by rule O6 |
| Media | measured through the proxy ([M1 media probe](2026-10-24-21-05-m1-media-probe.md)): `input_image` (data URL and https URL) and `input_file` (data URL and `file_url`) pass unchanged and are read (`gpt-5.6-luna`); audio and video input are not supported by plan usage ([OpenAI preview limitations](specs/openai-siwc-preview-limitations.md)) |

## openrouter

| | |
|---|---|
| Sign-in | `login openrouter`: the browser opens `https://openrouter.ai/auth` with a loopback `callback_url` (PKCE S256); the code is exchanged at `POST https://openrouter.ai/api/v1/auth/keys` for an API key labelled `accounts-proxy`, which does not expire (rules R5–R7). `--manual`: OpenRouter's headless page shows the code to paste. `--key`: an existing key at a hidden prompt, checked with `GET /api/v1/key`. `--from-opencode`: the key OpenCode stores |

## opencode

| | |
|---|---|
| Sign-in | `login opencode`: the OpenCode Console device login (RFC 8628) under the proxy's own client id `accounts-proxy`: `POST https://opencode.ai/console/auth/device/code` (`supports_org_scope=true`), the code is printed and the approval page opened, `POST /console/auth/device/token` is polled every interval (+5 s after `slow_down`); the sign-in is checked by reading the workspace configuration `GET /console/api/v2/config` (amendment A, K1–K6). `--key`: a service-account key `oc_sk_…` at a hidden prompt. `--from-opencode`: the key OpenCode stores (never its sign-in) |
| Credentials | `accounts-opencode.json`, shared with `opencode-go` (one Console account) |

| Native routes | per model: Chat → `/inference/openai/v1/chat/completions`, Responses → `/inference/openai/v1/responses`, Messages → `/inference/anthropic/v1/messages` (`count_tokens`: 400), Gemini → `/inference/google/v1beta/models/<model>:generateContent` / `:streamGenerateContent` (`:countTokens`: 400) with the key in `x-goog-api-key`, as OpenCode sends it (recon gap O4); the other routes carry it as `Authorization: Bearer` |

| Model list | the reference catalog models.opencode.ai — the list OpenCode itself loads at every start — its `opencode` provider: the ids and each model's format (its `provider.npm`, rule Z5), read now or stored within `modelListMaxAgeMinutes` (default 24 h); then the stored copy of this list; then the built-in copy (124 models). The gateway's `GET /inference/v1/models` is not read: OpenCode never reads it (recon gap O5) |
| Quota | not reported |
| Live findings | the free `*-free` models answer 403 `FreeTierError` "can only be used from within OpenCode" to any request that is not OpenCode's own (its `opencode/<version>` User-Agent and its own prompts), with the key `public` or a sign-in alike (Z8, Z21, [probe Z26](2026-10-19-17-18-z26-opencode-free-tier-probe.md)); since the proxy forwards the client's User-Agent, opencode through the proxy gets them, any other client gets the 403; `deepseek-v4-flash` and `kimi-k2.6` answered "Endpoint is unavailable" on 2026-10-13 |
| Media | measured through the proxy ([M1 media probe](2026-10-24-21-05-m1-media-probe.md)): on the Gemini format (`gemini-3.5-flash-lite`) inline images, PDFs, audio and video are read; on Chat (`glm-5.3-flash`) an image is read. The body is forwarded unchanged (rule G1) |
