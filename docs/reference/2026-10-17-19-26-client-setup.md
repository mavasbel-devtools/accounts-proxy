# accounts-proxy client setup

How to point SDKs and coding agents at the daemon. Every setup here was run against the daemon: the official SDKs in
the e2e tier and the live matrix (L1), Claude Code 2.1.29 and opencode 2.0.26 in the live validation (L3, C6, R7)
([findings](2026-10-13-02-52-live-validation-findings.md)). Kept current in place (decision D3). Related references:
[API](2026-10-17-19-26-proxy-api.md) · [providers](2026-10-17-19-26-providers.md) ·
[models](2026-10-17-19-26-models.md).

## 1. Start the daemon and get the token

```sh
bun run proxy serve          # foreground; Ctrl-C stops it
bun run proxy token          # the key every client sends
bun run proxy status         # running at http://127.0.0.1:4141 (providers: …)
```

| Client format | Base URL | Key carrier the SDK uses |
|---|---|---|
| Anthropic Messages | `http://127.0.0.1:4141/anthropic` (SDKs that append `/v1` themselves) or `…/anthropic/v1` | `x-api-key` |
| OpenAI Chat Completions, Responses | `http://127.0.0.1:4141/openai/v1` | `Authorization: Bearer` |
| Gemini | `http://127.0.0.1:4141/gemini` (the Gen AI SDK appends `/v1beta`) or `…/gemini/v1beta` | `x-goog-api-key` |

A model is `<provider>/<model>` (or an alias from `proxy.yaml`); which formats a model accepts is in
[models](2026-10-17-19-26-models.md). A model asked in a format it does not accept answers 400 `unsupported_feature`.

## 2. SDKs (TypeScript; the versions the tests pin)

```ts
import Anthropic from "@anthropic-ai/sdk"; // 0.133.0
const claude = new Anthropic({ apiKey: TOKEN, baseURL: "http://127.0.0.1:4141/anthropic" });
await claude.messages.create({ model: "claude/claude-haiku-4-5-20251001", max_tokens: 256, messages: [{ role: "user", content: "hi" }] });

import OpenAI from "openai"; // 7.32.0
const openai = new OpenAI({ apiKey: TOKEN, baseURL: "http://127.0.0.1:4141/openai/v1" });
await openai.chat.completions.create({ model: "openrouter/nvidia/nemotron-3.5-lightning:free", messages: [{ role: "user", content: "hi" }] });
await openai.responses.create({ model: "openai/gpt-5.6-luna", input: "hi" });

import { GoogleGenAI } from "@google/genai"; // 2.28.0
const gemini = new GoogleGenAI({ apiKey: TOKEN, httpOptions: { baseUrl: "http://127.0.0.1:4141/gemini" } });
await gemini.models.generateContent({ model: "antigravity/gemini-3.5-flash-lite", contents: "hi" });
```

The Gen AI SDK URL-encodes the model in the path (`antigravity%2Fgemini-3.5-flash-lite`); the proxy accepts it encoded
or raw.

## 3. HTTP directly

```sh
TOKEN=$(bun run --silent proxy token)
curl -s http://127.0.0.1:4141/health
curl -s -H "authorization: Bearer $TOKEN" http://127.0.0.1:4141/proxy/v1/models?provider=claude
curl -sN http://127.0.0.1:4141/anthropic/v1/messages -H "x-api-key: $TOKEN" -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model":"claude/claude-haiku-4-5-20251001","max_tokens":64,"stream":true,"messages":[{"role":"user","content":"Reply with OK."}]}'
curl -sN "http://127.0.0.1:4141/gemini/v1beta/models/antigravity%2Fgemini-3.5-flash-lite:streamGenerateContent?alt=sse" \
  -H "x-goog-api-key: $TOKEN" -H "content-type: application/json" \
  -d '{"contents":[{"role":"user","parts":[{"text":"Reply with OK."}]}]}'
```

## 4. Claude Code (Anthropic Messages)

```sh
ANTHROPIC_BASE_URL=http://127.0.0.1:4141/anthropic \
ANTHROPIC_API_KEY=$(bun run --silent proxy token) \
ANTHROPIC_DEFAULT_HAIKU_MODEL=claude/claude-haiku-4-5-20251001 \
claude --model claude/claude-haiku-4-5-20251001
```

- Any model that accepts Anthropic Messages works: `claude/…`, `openrouter/…`, the Messages models of `opencode`,
  `opencode-go` and `cheaper-inference` (measured: `opencode/claude-haiku-4-5`, `opencode-go/qwen3.8-flash`,
  `cheaper-inference/gpt-5.4-nano`). Set `ANTHROPIC_DEFAULT_HAIKU_MODEL` to a routable model too, as the measured
  setup did: a model id that is neither `<provider>/<model>` nor an alias answers 404 `unknown_model`.
- MCP tools work: Claude Code runs its MCP servers itself and sends their tools as ordinary tool definitions.
- `opencode-go` needs a session header Claude Code does not send; the proxy derives it (rule Z24), nothing to set.

## 5. opencode (v2)

**Well-known login (recommended).** opencode reads the proxy's `/.well-known/opencode`, runs `accounts-proxy token`
for the key, keeps it in `ACCOUNTS_PROXY_TOKEN`, and loads `GET /opencode/config.json` (refreshing it later; the last
good copy stays when the daemon is down):

```sh
opencode auth login http://127.0.0.1:4141
opencode models          # ap-claude/…, ap-antigravity/…, ap-openai/…, ap-openrouter/…, …
opencode run -m ap-claude/claude-haiku-4-5-20251001 "Reply with OK."
```

- One opencode provider `ap-<provider>` per proxy provider (`ap-claude` "Accounts Proxy · Claude", …), every model
  with its route, limits, media, price and opencode's own variants (`#low`, `#high`, …; none on Antigravity).
- `claude` and `openai` models carry `compatibility {supportsThinkingBlockBinding: false, supportsEffortUpdates:
  false}` (`openai`: `supportsEffortUpdates: false`), so Claude 5.1+ requests and switching variants mid-session work
  (rule O6).
- The first `opencode models` right after the login can show no `ap-` provider while opencode is still loading the
  configuration; the next call shows them (C6).

**Static file.** `bun run proxy opencode-config > providers.json` prints the same document for a config file; its
`apiKey` is `{env:ACCOUNTS_PROXY_TOKEN}`, so export the token under that name.

**By hand.** One custom provider per format, `options.baseURL` at the proxy and `options.apiKey` the token; model ids
are `<provider>/<model>`:

| AI SDK package | `baseURL` | Notes |
|---|---|---|
| `@ai-sdk/openai-compatible` | `http://127.0.0.1:4141/openai/v1` | Chat |
| `@ai-sdk/openai` | `http://127.0.0.1:4141/openai/v1` | Responses; for `openai/*` add `options.headers: {"x-proxy-lossy": "1"}`: the AI SDK sends `max_output_tokens`, which ChatGPT plan usage refuses (dropped and reported) |
| `@ai-sdk/anthropic` | `http://127.0.0.1:4141/anthropic/v1` | Messages; for `claude/*` set the model's `compatibility` as rule O6 does, or Claude 5.1+ requests answer 400 `unsupported_feature` |
| `@ai-sdk/google` | `http://127.0.0.1:4141/gemini/v1beta` | Gemini |

## 6. When a request is refused

| Answer | Meaning | What to do |
|---|---|---|
| 400 `unsupported_feature` … `_format` | the model does not accept this request format | use a format the model accepts ([models](2026-10-17-19-26-models.md)) |
| 400 `unsupported_feature` naming fields | the provider cannot carry them ([format fields](2026-10-17-19-26-format-fields.md)) | remove them, or send `x-proxy-lossy: 1` to drop them (listed in `x-proxy-dropped`) |
| 401 `unauthorized` | wrong or missing proxy token | `bun run proxy token` |
| 401 `provider_auth_required` | the provider needs a sign-in | `bun run proxy login <provider>` |
| 503 `provider_disabled` | not enabled in `proxy.yaml` | `enabled: true` (and `acknowledgeTermsRisk: true` on a subscription provider) |
| 429 with `retry-after` | the provider's quota | wait, or `bun run proxy account use <provider> <id>` |
