# accounts-proxy format fields reference

What the proxy does with every part of a request and an answer on each native cell (a provider × a request format it
accepts natively), field by field, with the rule or the evidence behind it. The proxy does not translate between
formats (plan 2026-10-16 D1-A): a format a model does not accept answers 400 `unsupported_feature` before anything here
applies. Kept current in place (decision D3). Related references: [API](2026-10-17-19-26-proxy-api.md) ·
[providers](2026-10-17-19-26-providers.md) · [models](2026-10-17-19-26-models.md).

Words used in the tables:

- **passes**: sent upstream as the client sent it.
- **refused**: 400 `unsupported_feature` naming the feature; with `x-proxy-lossy: 1` it is dropped instead and listed in
  `x-proxy-dropped` (strict translation, [AGENTS.md](../../AGENTS.md) §4).
- **always dropped**: removed whether or not the client sent `x-proxy-lossy`, and listed in `x-proxy-dropped`.
- **invalid**: 400 `invalid_request`.

## 1. claude × Anthropic Messages

Source: `packages/provider-claude/src/domain/request-transform.ts`, `model-envelope.ts` (ported from opencode-claude-auth
@ 6292741, differences F3, F4, F8, F9, F10 pinned by its parity test) and
`packages/provider-claude/src/adapters/outbound/claude-subscription-provider.ts`.

Request headers:

| Header | What the proxy does | Rule / evidence |
|---|---|---|
| `anthropic-version` | `2023-06-01` passes; any other value is refused | the captured client speaks 2023-06-01 (F4) |
| `anthropic-beta` | names in the model's captured beta set pass (client names first, then the rest of the set); any other name is refused as `anthropic-beta:<name>`; absent: the captured set | F4; the set per model in `model-envelope.ts` |
| the proxy token carriers | not forwarded; `authorization` carries the account's OAuth token | [API §1](2026-10-17-19-26-proxy-api.md#1-address-and-access) |
| every other client header | not forwarded: the proxy sends the Claude Code header set (`user-agent: claude-cli/<version> (external, <entrypoint>)`, `x-app: cli`, `anthropic-dangerous-direct-browser-access`, `x-stainless-*`, `x-cc-session-id`, `x-client-request-id`, `accept: text/event-stream`) | identity envelope, source `RequestTransformService.ts:187-298` |

Request body:

| Field | What the proxy does | Rule / evidence |
|---|---|---|
| (body) | must be a JSON object with a `messages` array, else invalid | |
| `model` | `<provider>/<model>` becomes the bare model id | |
| `messages` | the never-prefill guard: trailing `assistant` and `tool` messages removed; a `tool`-role message becomes a `user` message with one `tool_result` when it answers a `tool_use` id of the conversation, else it is removed; `tool_result` blocks of the last user message that answer no `tool_use` are removed; an empty result becomes one empty user message. Not listed in `x-proxy-dropped` | prefill guard L1–L3, source `RequestTransformService.ts:86-166` |
| `system` | the billing block and the identity block are put first; a string `system` follows as one text block, an array follows as it is | identity envelope |
| `max_tokens` | passes; absent: the model's envelope value (32000 or 64000; 32000 at most for a model the envelope does not know) | `model-envelope.ts` |
| `thinking` | absent stays absent. Otherwise rebuilt from scratch, which strips every other key (e.g. `block_binding`): `adaptive` → `{type, display}` (the client's `display`, else `omitted`); `enabled` → `{type, budget_tokens}` (the client's number from `budget_tokens` or `budgetTokens`, unclamped, else the envelope's, else 31999); `disabled` → `{type}`; any other type → the model's envelope thinking | AGENTS.md §3; F3; F9 (decision Q6) |
| `context_management` | thinking on (`adaptive` or `enabled`): replaced by `{edits:[{type:"clear_thinking_20251015",keep:"all"}]}`; thinking absent or `disabled`: passes (the proxy adds nothing) | F9: with the edit and thinking off the upstream answers 400 ([P0-LIVE L2](2026-10-10-23-17-p0-live-findings.md), [Q6 probe](2026-10-10-23-20-q6-thinking-probe.md)) |
| `output_config` | rebuilt as `{effort}` with the client's non-empty `effort` (every other key stripped); absent or without an effort: the model's envelope effort (`high`, `xhigh` on Opus 4.7), or left out on a model without one | `model-envelope.ts` |
| `metadata` | replaced by `{user_id: "{device_id, account_uuid, session_id}"}` (a JSON string) | identity envelope |
| `diagnostics` | replaced by `{previous_message_id}` (the id of the last answer this daemon streamed) | identity envelope |
| every other field (`tools`, `tool_choice`, `temperature`, `top_p`, `top_k`, `stop_sequences`, `stream`, `cache_control` in blocks, …) | passes. With thinking on, Anthropic itself refuses a `tool_choice` that forces tool use, `temperature` ≠ 1, `top_p` < 0.95 and `top_k` | [P0-LIVE L3](2026-10-10-23-17-p0-live-findings.md) |
| URL | `?beta=true` is appended | captured client |
| `count_tokens` | the same envelope without the fields the proxy adds only for Messages: no default `max_tokens`, no clear-thinking `context_management`, no `metadata`, no `diagnostics` (the client's own fields still pass, and the upstream refuses those outside the spec's body parameters) | F10: the upstream answered 400 `Extra inputs are not permitted` to `max_tokens` and `diagnostics`, 200 without them ([P6 probe](2026-10-18-18-39-p6-count-tokens-probe.md)) |

Answer: the status and the body unchanged (an event stream chunk by chunk); headers `content-type`, `retry-after`,
`request-id`, `anthropic-ratelimit-*`, and `x-proxy-dropped` for the refused names dropped under `x-proxy-lossy`. An
upstream 401 renews the token once and resends the request, before anything reached the client (plan v4 H-d).

## 2. antigravity × Gemini

Source: `packages/provider-antigravity/src/domain/native-gemini.ts` (P4 plan §2.3), `gemini-schema.ts`,
`trajectory.ts`. Every key outside the lists below is refused: nothing the IDE never sent and no live probe accepted
is forwarded (P4 plan §2.3, decision Q2).

| Field | What the proxy does | Rule / evidence |
|---|---|---|
| top-level keys | `contents`, `systemInstruction`, `tools`, `toolConfig`, `generationConfig`; every other key (`safetySettings`, `cachedContent`, …) refused | captured IDE request |
| `contents[].role` | `user` (default when absent) or `model`; any other value invalid | |
| `contents[].parts[]` keys | `text`, `thought`, `thoughtSignature`, `inlineData` (string `mimeType` and `data`), `functionCall` and `functionResponse` (string `name`); any other key (`fileData`, `executableCode`, …) refused | captured IDE request |
| `functionResponse` parts | a run of them in a `user` content moves to a `model`-role content | wire law 7 |
| `functionCall` without `thoughtSignature` (Gemini models) | signed with the signature the proxy captured for its id, else always dropped together with its `functionResponse` (`unsigned_function_call:<id or name>`) | wire law 6 |
| contents with no content (no call, response, inline data or non-blank text) | always dropped (`empty_content`) | wire law 8 |
| trailing `model` contents that are not function responses | always dropped (`trailing_model_turn`); nothing left is invalid | wire law 12 |
| `systemInstruction` | a content whose parts hold only `text`; another part key is refused (under lossy the part keeps its text); sent as a `user`-role content | captured IDE request |
| `tools[]` | only `functionDeclarations` (every other tool, e.g. `googleSearch`, `codeExecution`, refused); all declarations are sent as one tool | captured IDE request |
| declaration keys | `name` (required string), `description`, `parameters`, `parametersJsonSchema`; another key is refused | |
| `parameters` | keywords outside `type, format, description, nullable, enum, items, properties, required, propertyOrdering` are refused (lossy: removed); `type` values are upper-cased | wire law 5, decision Q2 |
| `parametersJsonSchema` | passes unchanged (the Gen AI SDK's form of every `$schema` / MCP tool) | [live validation F2](2026-10-13-02-52-live-validation-findings.md) j1–j4 |
| `toolConfig` | only `functionCallingConfig`; `mode` `AUTO` or `VALIDATED` passes; any other mode and `allowedFunctionNames` refused; with tools and no mode: `VALIDATED` | [P0-LIVE L6](2026-10-10-23-17-p0-live-findings.md) |
| `generationConfig` keys | `maxOutputTokens`, `thinkingConfig`, `temperature`, `topP`, `topK`, `stopSequences`; another key (`responseMimeType`, `responseSchema`, `candidateCount`, …) refused | captured IDE request; E3 f6/f7 |
| `maxOutputTokens` | a positive integer up to the catalog's maximum passes; above it refused (lossy: the maximum); absent: the catalog's maximum | P4 plan §2.3 |
| `thinkingConfig` | keys `includeThoughts` (boolean), `thinkingBudget` (integer); another key refused; a budget other than the catalog's is refused (lossy: the catalog's); on a model with a catalog budget the budget is always sent and `includeThoughts` defaults to `true` | AGENTS.md §3 (catalog-exact budget), wire law 13 |
| `temperature`, `topP`, `topK` (numbers), `stopSequences` (strings) | pass | E3 f6/f7 |
| envelope | the inner request gets the trajectory `labels` and `sessionId` (int64 as a decimal string); it is wrapped as `{project, requestId, request, model, userAgent: "antigravity", requestType: "agent"}` with the account's Cloud Code project and the IDE's `user-agent` header | trajectory rules `TrajectoryStateService.ts:64-204`; `upstream.ts` |
| `?alt` | `sse`: the answer is Server-Sent Events; otherwise a JSON array | Gemini REST |

Answer: each upstream envelope's `response` (the public `GenerateContentResponse`) as it arrives;
`:generateContent` merges the stream into one response (consecutive text parts with the same `thought` flag joined,
every other part kept in order, the last finish reason, usage, model version and response id; decision Q4). Signatures
of returned function calls are stored for later turns. Headers: `content-type` and `x-proxy-dropped`.

## 3. openai × OpenAI Responses

Source: `packages/provider-openai/src/domain/responses.ts`, `constants.ts` and
`packages/provider-openai/src/adapters/outbound/openai-provider.ts`; rules I2–I6 and E2 in
[the OpenAI rules](2026-10-11-23-08-openai-chatgpt-plan-rules.md) (from OpenAI's plan-usage documentation in
`docs/reference/specs/openai-siwc-*.md`).

| Field | What the proxy does | Rule / evidence |
|---|---|---|
| any field set to `null` | left out (the API's "not set") | |
| `model` | the bare model id | |
| `stream` | must be a boolean; upstream always `true`; the client's value decides whether the client gets the stream or one merged response | I2, decision O8 |
| `store` | absent or `false` passes as `false`; any other value refused | I2 |
| `background`, `conversation`, `max_output_tokens`, `max_tool_calls`, `metadata`, `moderation`, `multi_agent`, `prompt`, `prompt_cache_retention`, `safety_identifier`, `temperature`, `top_logprobs`, `top_p`, `truncation`, `user`, `previous_response_id` | refused | I3 (preview limitations) |
| `input` | an array passes; a string becomes `[{role:"user",content:<string>}]`; anything else invalid | I2; openai-openapi.yaml `input` |
| `input` items with role `system` | refused | I3 |
| `tools[]` of type `image_generation`, `file_search`, `code_interpreter`, `computer`, `computer_use_preview`, `mcp`, `tool_search`, `programmatic_tool_calling` | refused (lossy: removed from the list) | I4 |
| `tool_choice` naming one of those types | refused | I4 |
| every other field (`instructions`, `reasoning`, `text`, `include`, function `tools`, `parallel_tool_calls`, `prompt_cache_key`, …) | passes | |
| headers | `session-id`, `thread-id`, `x-client-request-id`: the client's, else the daemon's session id; `user-agent: accounts-proxy/0.1.0`; no other client header | decision O9 |

Answer: a streaming client gets the upstream frames as they complete; a terminal `response.completed` or
`response.incomplete` whose `response.output` is empty gets the items of the `response.output_item.done` events, in
`output_index` order (rule I6). A non-streaming client gets the terminal `response` (filled the same way) as one JSON
answer; `response.failed` or `error` answers `{"error":{message, type:"response_failed", param, code}}` with the
status of the documented code (E2: e.g. `subscription_sharing_usage_limit_exceeded` 429), else 502; a stream without a
terminal event is 502. An upstream error status passes unchanged. Headers: `content-type` (`text/event-stream` for a
streaming client when plan usage sends none, `application/json` for a merged answer; rule I7), `retry-after`,
`x-oai-request-id`, `x-request-id` when present, `x-proxy-dropped`.

## 4. API-key gateways

Source: `packages/provider-gateway/src/domain/gateway.ts` (rules G1–G4, R1, C1, Z12–Z15, Z20, Z24 in
[the gateway rules](2026-10-12-15-35-gateway-provider-rules.md)) and the vendor specs in
`packages/provider-{openrouter,opencode,cheaper-inference}/src/domain/`. The gateways serve the formats natively, so
the proxy changes only what routing needs.

| Part | What the proxy does | Rule |
|---|---|---|
| `model` (body; Gemini: the path) | `<provider>/<model>` becomes the vendor's bare id | G1 |
| every other body field | passes (Messages, Chat, Responses: the JSON re-serialized with the new `model`; Gemini: the body byte for byte) | G1 |
| query | Gemini: only `alt` is kept; the other formats send no query | G4 |
| `authorization` | `Bearer <the account's key or Console token>` on every endpoint | R1, C1, Z14 |
| `content-type` | `application/json` | G2 |
| `accept` | the client's, when sent | G2 |
| `anthropic-version`, `anthropic-beta` | the client's, on Messages only | G2 |
| `user-agent` | `opencode`, `opencode-go`: `accounts-proxy/0.1.0`; the other gateways: the HTTP client's default (the proxy sets none) | Z15 |
| workspace headers | `opencode`, `opencode-go`: the headers of the workspace's Console configuration (`x-opencode-org-id`) | Z13, Z20 |
| `x-opencode-session` | `opencode`, `opencode-go`: the client's; else Claude Code's session from `metadata.user_id` (Messages), the `prompt_cache_key` (Responses), else `ap_` + the 64-bit FNV-1a hash of the first user turn | Z15, Z24 |
| every other client header | not forwarded | G2 |
| `count_tokens` | `cheaper-inference` only; elsewhere refused (no lossy fallback: the route has no other meaning) | C2 |
| Gemini methods | `generateContent`, `streamGenerateContent` (on `opencode`); `countTokens` refused | G4 |

Answer: the status and the body unchanged, streamed as they arrive; headers `content-type`, `retry-after` and the
vendor's request id (`x-generation-id`, `x-opencode-log-id`, `x-ci-request-id`) (G3). Nothing is dropped, so no
`x-proxy-dropped`.

Endpoints per vendor:

| Format | `openrouter` (`https://openrouter.ai/api/v1`) | `opencode` (`https://opencode.ai/inference`) | `opencode-go` (`https://opencode.ai/inference/go`) | `cheaper-inference` (`https://api.cheaperinference.com/v1`) |
|---|---|---|---|---|
| Messages | `/messages` | `/anthropic/v1/messages` | `/v1/messages` | `/messages` (+ `/messages/count_tokens`) |
| Chat | `/chat/completions` | `/openai/v1/chat/completions` | `/v1/chat/completions` | `/chat/completions` |
| Responses | `/responses` | `/openai/v1/responses` | `/v1/responses` | `/responses` |
| Gemini | — | `/google/v1beta/models/<model>:<method>` | — | — |
| which models | every model, every format (R2) | per model, from the reference catalog (Z5) | per model, from the reference catalog (Z5) | per model, from its `endpoint`/`supported_endpoints` (C3) |
