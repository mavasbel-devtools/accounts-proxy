# accounts-proxy API reference

The daemon's HTTP API, the command line, the configuration and the data directory, as the code implements them
(commit of this document and later; kept current in place, plan 2026-10-16 decision D3). The machine-readable form of
the HTTP API is [the OpenAPI 3.1 document](2026-10-17-19-26-proxy-openapi.json). Related references:
[providers](2026-10-17-19-26-providers.md) · [format fields](2026-10-17-19-26-format-fields.md) ·
[models](2026-10-17-19-26-models.md) · [client setup](2026-10-17-19-26-client-setup.md).

Kept in step with the code by `apps/proxy/tests/unit/docs-in-step.test.ts` (routes, error codes and statuses, headers,
commands, environment variables, limits) and `apps/proxy/tests/e2e/docs.test.ts` (every OpenAPI operation against the
real daemon, the generated model reference), both part of `bun run verify`.

## 1. Address and access

- The daemon (`bun run proxy serve`) listens on `127.0.0.1` only, on `port` from `proxy.yaml` (default `4141`). A port
  already in use (`EADDRINUSE`) stops it with an error; it never picks another port.
- Every route except `GET /health` and `GET /.well-known/opencode` needs the **proxy token**: the value
  `bun run proxy token` prints (stored in `<data>/token.json`, mode 0600, created on first `serve` or `token`). It is
  compared in constant time and read from the first carrier that has one:

  | Carrier | Sent by |
  |---|---|
  | `Authorization: Bearer <token>` | the OpenAI SDK, opencode, curl |
  | `x-api-key: <token>` | the Anthropic SDK, Claude Code |
  | `x-goog-api-key: <token>` | the Google Gen AI SDK |
  | `?key=<token>` | Gemini REST clients; the proxy removes it from the query before the request goes upstream |

  A missing or wrong token answers 401 `unauthorized` in the route's error shape (§5).

## 2. Models are addressed as `<provider>/<model>`

- A request names its model as `<provider>/<model>`, split at the **first** `/` (OpenRouter ids keep theirs:
  `openrouter/nvidia/nemotron-3.5-lightning:free`). The provider is one of `claude`, `antigravity`, `openai`,
  `openrouter`, `opencode`, `opencode-go`, `cheaper-inference`.
- A bare name is looked up in `aliases` of `proxy.yaml` (§7), whose values are `<provider>/<model>`. Anything else is
  404 `unknown_model`; nothing is guessed.
- A provider that is not enabled answers 503 `provider_disabled`.
- **No translation between formats.** A model accepts some request formats natively (one fixed format on `claude`,
  `antigravity`, `openai`; per model, or every format, on the gateways). A request in another format answers 400
  `unsupported_feature`, e.g. `claude/claude-haiku-4-5 (it accepts anthropic-messages; the proxy does not translate
  between formats) cannot carry: openai-chat_format`. A gateway model whose formats no source states is forwarded in
  the client's format (rule Z6). Which model accepts which format: [models](2026-10-17-19-26-models.md).

## 3. Routes

| Method and path | Format | Answer |
|---|---|---|
| `GET /health` | | `{"status":"ok","providers":[…enabled providers]}`; no token |
| `GET /.well-known/opencode` | | the manifest `opencode auth login http://127.0.0.1:<port>` reads: the command that prints the token and the configuration URL (decision E1); no token |
| `GET /opencode/config.json` | | the opencode v2 configuration of every model ([rules O1–O6](2026-10-16-01-38-model-catalog-rules.md)) |
| `GET /proxy/v1/models` (`?provider=<id>`) | | `{"catalogs":[…]}`: every enabled provider's models in detail, each field with its source; an unknown `provider` is 400 `invalid_request` |
| `POST /proxy/v1/models/refresh` (`?provider=<id>`) | | `{"catalogs":[…]}` in the shape of `GET /proxy/v1/models`, after every enabled provider's list (or the one named) and the reference catalog were read now from their sources instead of reusing a copy younger than `modelListMaxAgeMinutes` (§7); a failed read keeps the stored copy, then the built-in list; a provider that cannot list is `unavailable`; asked by name, its error; an unknown `provider` is 400 `invalid_request`, a disabled one 503 `provider_disabled` |
| `POST /anthropic/v1/messages` | Anthropic Messages | the provider's answer |
| `POST /anthropic/v1/messages/count_tokens` | Anthropic Messages | the provider's answer (`claude`, `cheaper-inference`; others 400 `unsupported_feature`) |
| `GET /anthropic/v1/models` | | every enabled provider's models, Anthropic `ListModels` shape |
| `POST /openai/v1/chat/completions` | OpenAI Chat Completions | the provider's answer |
| `POST /openai/v1/responses` | OpenAI Responses | the provider's answer |
| `GET /openai/v1/models` | | every enabled provider's models, OpenAI `ListModelsResponse` shape |
| `POST /gemini/v1beta/models/{model}:generateContent` | Gemini | the provider's answer |
| `POST /gemini/v1beta/models/{model}:streamGenerateContent` | Gemini | the provider's answer: SSE with `?alt=sse`, else one JSON array written as the stream arrives |
| `POST /gemini/v1beta/models/{model}:countTokens` | Gemini | 400 `unsupported_feature` on every provider |
| `GET /gemini/v1beta/models` | | every enabled provider's models, Gemini `ListModels` shape |

- `{model}` is `<provider>/<model>`, URL-encoded (`antigravity%2Fgemini-3.5-flash-lite`) or raw; the route takes the
  model up to the last `:`.
- Every other `POST /anthropic/v1/…` path goes to the model's provider, which answers 400 `invalid_request` ("has no
  native route"). Any other method or path answers 404 `not_found`: under a dialect prefix in the dialect's error shape,
  after the token check (so a request without the token gets 401 there); elsewhere, and for another method on the
  proxy's own routes, as plain JSON.
- **Model lists** (`GET …/models`) list the models of every enabled provider in that dialect's shape, whatever formats
  they accept. Fields a catalog does not state are neutral markers, never invented values (decision Q5): Anthropic
  `created_at: "1970-01-01T00:00:00Z"`, OpenAI `created: 0`, Gemini `version` = the provider id; Gemini
  `baseModelId` is the routable `<provider>/<model>` and `supportedGenerationMethods` is empty for a model that does not
  accept the Gemini format. The answer carries `x-proxy-models-source` (§4).
- **Pass-through answers.** On a native cell the provider's answer reaches the client as it arrives: its status, its
  body (an event stream chunk by chunk) and the response headers listed per provider in
  [providers](2026-10-17-19-26-providers.md). Upstream errors (400, 401, 403, 429 with `retry-after`, 5xx) are among
  them: they keep the provider's status, body and `retry-after`. Three providers change the answer, each for a rule:
  `openai` fills an empty terminal `output` (rule I6) and merges the stream for a non-streaming client (decision O8;
  a `response.failed` or `error` event then answers `{"error":{"message","type":"response_failed","param","code"}}`
  with the status of the documented code, else 502), and `antigravity` unwraps its envelope and merges the stream for
  `generateContent` (decision Q4).
- **Client disconnect.** A client that closes its connection aborts the upstream request; nothing is logged as an
  error for it.

## 4. Proxy headers

| Header | Direction | Meaning |
|---|---|---|
| `x-proxy-lossy: 1` | request | drop, instead of answering 400 `unsupported_feature`, what the target cannot carry |
| `x-proxy-dropped` | response | every feature or element removed from the request, comma-separated: lossy drops and the wire laws that always apply (unsigned Gemini function calls, empty contents, trailing model turns on `antigravity`) |
| `x-proxy-models-source` | response of `GET …/models` | one `<provider>=<source>` pair per enabled provider, comma-separated, e.g. `claude=live,antigravity=live,openai=cache`; source is `live`, `cache` (the stored copy, reused for `modelListMaxAgeMinutes`, default 24 h), `static` (the built-in list) or `unavailable` |
| `retry-after` | response | seconds to wait: the provider's, passed through, or the proxy's on 429 `quota_exhausted` |

## 5. Errors

The proxy's own errors use the error shape of the route's dialect; the status and the code are the same in every
shape. An error the provider answered is not one of these: it passes through in the provider's own shape (§3).

| Status | Code | When |
|---|---|---|
| 400 | `invalid_request` | the request cannot be read: not JSON, no string `model`, a malformed field, a path the provider has no native route for, an unknown `?provider=` |
| 400 | `unsupported_feature` | a format the model does not accept, or a field, tool, header or value the target cannot carry ([format fields](2026-10-17-19-26-format-fields.md)); the message lists them |
| 401 | `unauthorized` | missing or wrong proxy token |
| 401 | `provider_auth_required` | the provider has no usable login: no account, an unreadable one, or one whose refresh was rejected (`account list` shows `[needs login: …]` until `login <provider>`) |
| 404 | `unknown_model` | not `<provider>/<model>` and not an alias; or a model `antigravity` does not list |
| 404 | `unknown_account` | `account use` or `account remove` with an account id the provider does not have (command line) |
| 404 | `not_found` | no such route |
| 413 | `payload_too_large` | a request body over 32000000 bytes |
| 429 | `quota_exhausted` | `antigravity` reported its quota exhausted (with `retry-after` when it states one); the other providers' 429 passes through unchanged. No provider switches accounts by itself |
| 500 | `internal_error` | a proxy defect; the client sees a fixed text, the details are in `logs/proxy.log` |
| 502 | `upstream_unreachable` | no HTTP answer from the provider: DNS, refused, reset, TLS |
| 503 | `provider_disabled` | the provider is not enabled in `proxy.yaml` |
| 504 | `upstream_timeout` | the provider sent nothing for 600000 ms (10 minutes) |
| the provider's status, else 502 | `upstream_error` | `antigravity` answered an error, a malformed or an empty stream; or a token endpoint failed during a request (the renewal of `claude`, `antigravity`, `openai`, `opencode`/`opencode-go`) with a status that is not a rejected refresh |

Shapes (`message` is the same text in each):

| Where | Body |
|---|---|
| `/anthropic/*` | `{"type":"error","error":{"type":"<Anthropic type of the status>","message":"…"}}`; types from [anthropic-errors](specs/anthropic-errors.md): 400 `invalid_request_error`, 401 `authentication_error`, 402 `billing_error`, 403 `permission_error`, 404 `not_found_error`, 409 `conflict_error`, 413 `request_too_large`, 429 `rate_limit_error`, 500 `api_error`, 504 `timeout_error`, 529 `overloaded_error`, any other status `api_error` |
| `/openai/*` | `{"error":{"message":"…","type":"<code>","param":null,"code":"<code>"}}` |
| `/gemini/*` | `{"error":{"code":<status>,"message":"…","status":"<google.rpc.Code name>"}}` (400 `INVALID_ARGUMENT`, 401 `UNAUTHENTICATED`, 403 `PERMISSION_DENIED`, 404 `NOT_FOUND`, 409 `ABORTED`, 429 `RESOURCE_EXHAUSTED`, 499 `CANCELLED`, 500 `INTERNAL`, 501 `UNIMPLEMENTED`, 503 `UNAVAILABLE`, 504 `DEADLINE_EXCEEDED`, any other `UNKNOWN`); an `antigravity` error body that already is this envelope is passed verbatim |
| the proxy's own routes and any other path | `{"error":{"code":"<code>","message":"…"}}` |

An `antigravity` stream that fails after its first byte ends with one more frame carrying the Google envelope (the
status line was already sent).

## 6. Command line

`bun run proxy <command>` (the workspace declares the `accounts-proxy` bin). Exit codes: 0 success and every help, 1
the command failed (`error: <message>` on stderr), 2 usage error (the message, the usage of the command it belongs to
and `for options, exit codes and examples: bun run proxy help <command>` on stderr; a misspelt command or subcommand
also gets `(did you mean <name>?)` when one name is at most two edits away).

Every command and subcommand has its own help: `bun run proxy help <command> [<subcommand>]`, `<command> --help` and
`<command> -h` print the same text on stdout and exit 0 without running the command (also after other arguments, so
`serve --help` never starts the daemon; after `--` a help flag is an ordinary argument). The help has the command's
usage, description, arguments, options with their defaults, exit codes, environment variables and runnable examples.
With no command, `help`, `--help` and `-h` print the overview of every command.

| Command | What it does |
|---|---|
| `login <provider> [--manual] [--new] [--key] [--from-opencode] [--timeout-seconds N]` | signs in and makes the account the active one; waits up to 300 s by default (`--timeout-seconds N`, a positive integer). The method per provider is in [providers](2026-10-17-19-26-providers.md): browser sign-in with a loopback listener on `127.0.0.1` (`claude`, `antigravity`, `openai`, `openrouter`; the URL is printed too), the OpenCode Console device login (`opencode`, `opencode-go`: the code is printed and the approval page opened), or an API key at a hidden prompt (`cheaper-inference`). `--manual`: paste the code instead of the loopback listener (`claude`, `openrouter`). `--new`: register another ChatGPT account (`openai`). `--key`: enter an API key at a hidden prompt (gateways). `--from-opencode`: import the API key OpenCode stores in its `auth.json`, once (gateways; never a sign-in token). `--key` and `--from-opencode` exclude each other |
| `account list <provider>` | the stored accounts; `*` marks the active one, `[needs login: …]` one whose refresh was rejected |
| `account use <provider> <account-id>` | chooses the active account (the proxy never switches accounts by itself) |
| `account remove <provider> <account-id>` | deletes a stored account and its tokens (the provider's own sign-in is not revoked); when it was the active one, no account is active afterwards and requests answer 401 `provider_auth_required` until `account use` or `login` |
| `quota <provider>` | the remaining quota as the provider reports it: `antigravity` (per model group), `openrouter` (key usage and limit), `cheaper-inference` (wallet); any other provider fails with `<provider> does not report usage` |
| `models [<provider>] [--json] [--refresh]` | each provider's models with context and output limits and where the list came from (live catalog, stored copy, built-in list, or unavailable with the reason); `--json`: the detailed records of `GET /proxy/v1/models`. `--refresh`: every list read now from its source; the running daemon on the configured port does it (`POST /proxy/v1/models/refresh`, with the proxy token and a 300000 ms deadline), so its lists and the opencode configuration change at once; when nothing listens there, the command itself does it and rewrites the stored copies a daemon reads when it starts. The first line names which one refreshed (`--json`: `refreshedBy` `daemon` or `this process`, and `url`) |
| `opencode-config` | prints the document of `GET /opencode/config.json` |
| `serve` | runs the daemon in the foreground; Ctrl-C (SIGINT) or SIGTERM stops it and in-flight responses get 10000 ms (10 s) to finish |
| `token` | prints the proxy token (created on first use) |
| `status` | `GET /health` on the configured port with a 2000 ms deadline: `running at … (providers: …)`, else `not running at … (<reason>)` and exit 1 |
| `help [<command> [<subcommand>]]` | the help of the program (also with no command, `--help`, `-h`) or of one command; `<command> --help` and `<command> -h` print the same |

## 7. Configuration: `<data>/proxy.yaml`

Validated strictly: an unknown key or a wrong type is an error naming it. No file means every provider is disabled.
Example: [config/proxy.example.yaml](../../config/proxy.example.yaml).

| Key | Value |
|---|---|
| `port` | integer 1–65535; default 4141 |
| `providers.<id>.enabled` | `true` starts the provider; default `false` |
| `providers.<id>.acknowledgeTermsRisk` | required `true` with `enabled: true` on the subscription providers `claude`, `antigravity`, `openai`: their terms restrict third-party clients ([research](../research/2026-10-05-20-07-llm-router-from-auth-plugins.md) §3) |
| `aliases.<name>` | `<provider>/<model>`; a request may then name the model `<name>` |
| `modelListMaxAgeMinutes` | positive integer; default 1440 (24 h): how long a fetched model list and the reference catalog are reused before the next request reads them again; `models --refresh` reads them at once |
| `exchangeLog.enabled` | `true` or `false`; default `true`: every HTTP exchange is written to `logs/exchanges-YYYY-MM-DD.jsonl` (§8) |
| `exchangeLog.retentionDays` | positive integer; default 14: day files older than this many days (today included) are deleted at the first write of each day |

## 8. Data directory

`~/.local/share/accounts-proxy/` (`ACCOUNTS_PROXY_HOME` overrides it). The proxy creates its directories with mode 0700
and its files with mode 0600; it never writes Claude Code's, OpenCode's or the plugins' files.

| Path | Content |
|---|---|
| `proxy.yaml` | the configuration (§7) |
| `token.json` | the proxy token |
| `accounts-<provider>.json` | the proxy's own accounts, tokens and API keys (`opencode-go` uses `accounts-opencode.json`); written only by a locked read-change-write |
| `state/` | per-install provider state: device and session ids, model-list copies, the reference model catalog copy, Antigravity thought signatures |
| `locks/` | cross-process lock files (token renewal, account files) |
| `logs/proxy.log` | the log; it never contains tokens or keys |
| `logs/exchanges-YYYY-MM-DD.jsonl` | the exchange log (UTC day; `exchangeLog` in §7; [plan](../plans/2026-10-26-23-00-exchange-log-plan.md)): one JSON line per record, `schema` `accounts-proxy-exchange/1`, `at`, `pid`, `kind`, `id`. Kinds: `client-request` / `client-response` (a request to the daemon and its answer), `upstream-request` / `upstream-response` (every request the proxy sends — model calls, token renewals, logins, model lists, quota, the reference catalog — from the daemon and every command; `exchange` names the client request it was made for), `login-callback` (the browser's return to the loopback listener) and `browser-open`. A record holds the method, URL or path and query, every header (the client's in the order and case it sent them), the whole body (UTF-8 text, else base64; a zstd request body's text also as `decodedBody`), each answer chunk's time and size, the status, `outcome` (`complete`, `aborted`, `failed` with `error`), the timings (`startedAt`, `requestBodyMs`, `headersMs`, `firstByteMs`, `totalMs`) and, for model answers, `usage.raw` (the provider's fields verbatim) and `usage.tokens` (`input`, `output`, `cacheRead`, `cacheWrite`, `cacheWrite5m`, `cacheWrite1h`, `reasoning`, `toolUsePrompt`, `total`; a count the answer does not state is absent). Credential headers, token and key fields and every value with a known token prefix are replaced by `[redacted sha256:<12 hex> len:<n>]`; prompts, answers and account ids are kept. Writing never fails a request |

## 10. Limits and timers

| Value | Where |
|---|---|
| request body: 32000000 bytes | larger answers 413 `payload_too_large` |
| upstream idle timeout: 600000 ms | no byte from the provider for this long answers 504 `upstream_timeout` |
| shutdown grace: 10000 ms | in-flight responses after SIGINT/SIGTERM |
| login wait: 300 s | `login`, unless `--timeout-seconds` |
| access-token renewal: 2 minutes before expiry | once for all concurrent requests and processes; each token call is bounded by 30 s; a transient renewal failure keeps a still-valid token and retries after 30 s; a rejected refresh marks the account `needs login` ([AGENTS.md](../../AGENTS.md) §4 Sessions) |
| model lists and the reference catalog: `modelListMaxAgeMinutes`, default 1440 minutes (24 h) | the stored copy is reused that long (§7); a failed live fetch falls back to the stored copy, then to the built-in list; `models --refresh` reads them now |
| model refresh: 300000 ms | the deadline of `models --refresh` for the running daemon's answer (`POST /proxy/v1/models/refresh` reads every list) |
