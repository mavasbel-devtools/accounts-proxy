## 1. What the e2e tier is

- The real entry `apps/router/src/main/cli.ts` runs as a child process under `--preload scripts/gate/e2e-coverage-preload.ts`
  (every source file it loads is instrumented; coverage is written on its normal exit). The built bundle cannot carry
  per-source instrumentation, so `apps/router/tests/e2e/bundle.test.ts` runs the bundle separately (help, serve,
  `/health`, SIGTERM) without adding coverage. This differs from plan §3, which named the bundle as the e2e target.
- Every upstream is one loopback replay server (`tests/support/e2e/upstreams.ts`) behind the composition root's
  `INFERENCE_ROUTER_TEST_UPSTREAM_*` seams; it answers only from committed captures (plugin fixtures, P0-LIVE captures).
- Browser logins run through a fake `xdg-open` first on `PATH` (`tests/support/e2e/fake-browser.ts`); the paste-code
  login reads `code#state` from stdin.
- Clients: `@anthropic-ai/sdk` 0.133.0, `@google/genai` 2.28.0, `openai` 7.32.0, plus raw HTTP for the byte framing.

Measured client behaviour (the open questions of plan §2.1): `@google/genai` 2.28.0 sends the model segment raw
(`/v1beta/models/antigravity/gemini-3.6-flash-low:generateContent`), the key in `x-goog-api-key`, and `?alt=sse` for
streams; `@anthropic-ai/sdk` sends `x-api-key` and `anthropic-version: 2023-06-01`; `openai` sends `Authorization: Bearer`.

**Kind 1 (P5 only): deferred, not excluded.** `scripts/gate/e2e-deferred.ts` lists every entry with its phase and reason:
whole files, single functions (resolved from their declarations), or single branches named by their exact source line
(the branch's unrun statements on that line go with it). An entry is *stale*, and fails the gate, when e2e covers it or
when its name no longer matches exactly one function or branch. The list must be empty when P5 is done. Today's 11
entries: `feature-support.ts`, `usage.ts`, `generate.ts`, `antigravity-chat.ts` (files); `event-stream.ts`
`end`/`encode`, `catalog.ts` `wireDefaultsFor`, both providers' `capabilities`/`stream`/`countTokens` (functions); the
retry-after header of the Anthropic and OpenAI error encoders and the runner's skip of content-free envelopes
(branches: a router error with retry-after comes only from Antigravity, which those dialects reach only in P5).

**Kind 2 (reachable): black-box scenarios.** New e2e files `claude-cell`, `gemini-cell`, `sessions`, `cli-errors`,
`antigravity-edges`, `claude-edges` and `router-edges` drive each validation and error path through the real process:
odd upstream shapes come from the replay server's scripted answers, stored-state faults from files written, made
read-only or replaced by directories in the data directory, and lock races from lock files the test holds and releases.

**Kind 3 (not reachable from outside).** Two remedies:
- *Removed* where no deployed path can take the branch (commits `0560147`, `40bab43`): the Claude transform takes the
  router's real arguments; one PKCE pair per login; caught values are read as `Error`s (`errorMessage`); constant
  lock and state names need no runtime check; `rotated()` alone keeps the previous refresh token; fetch always
  combines the client signal and the deadline; the trajectory needs no guards for states `begin` rules out; one
  `parseJsonBody` for the three request parsers.
- *Hermetic test hooks* (commit `294cffb`, plus `INFERENCE_ROUTER_TEST_LISTEN_UNASSIGNED`): read only by `main()`,
  accepted only together with all four upstream seams (so a process that can reach a real provider never runs with
  one), and validated. `INFERENCE_ROUTER_TEST_PLATFORM` (linux, darwin, win32 browser openers),
  `INFERENCE_ROUTER_TEST_UPSTREAM_IDLE_MS` (the 504 paths), `INFERENCE_ROUTER_TEST_LOCK_TIMEOUT_MS` (lock timeout),
  `INFERENCE_ROUTER_TEST_LOCK_STAT_VANISHES=1` (a lock released between the failed create and the stale check),
  `INFERENCE_ROUTER_TEST_LISTEN_UNASSIGNED=1` (the daemon binds `192.0.2.1`, RFC 5737 TEST-NET-1, never assigned to a
  host, so listen fails with an error other than `EADDRINUSE`; this machine allows unprivileged ports from 0,
  `/proc/sys/net/ipv4/ip_unprivileged_port_start` = 0, so no loopback port is refused).

**Defects the new scenarios found, fixed in the same change:**
- *Signature store race.* `saveSignature` is fire-and-forget; concurrent saves wrote overlapping snapshots, so an
  older one could land last and lose signatures (seen with 2001 signed calls in one answer), and concurrent first
  loads could each install their own map. Now the store is read once, writes never overlap, a burst is coalesced into
  one queued write that stores the map as it is when it starts, and a failed write rejects only its own callers.
- *Bun 1.4.2 fetch idle timer granularity* (measured with `scripts/evidence/bun-fetch-idle-probe.ts`): a 500 ms or 3 s
  `timeout` fired after ~8 s, both before the headers and mid-body. The production value (10 minutes) is far above
  that; the e2e idle tests wait 15 s. The replay server now runs with `idleTimeout: 0` so its own 10 s default cannot
  close a deliberately silent answer first.
