## 1. What the e2e tier is

- The real entry `apps/router/src/main/cli.ts` runs as a child process under `--preload scripts/gate/e2e-coverage-preload.ts`
  (every source file it loads is instrumented; coverage is written on its normal exit). The built bundle cannot carry
  per-source instrumentation, so `apps/router/tests/e2e/bundle.test.ts` runs the bundle separately (help, serve,
  `/health`, SIGTERM) without adding coverage. This differs from plan §3, which named the bundle as the e2e target.
- Every upstream is one loopback replay server (`tests/support/e2e/upstreams.ts`) behind the composition root's
  `INFERENCE_ROUTER_TEST_UPSTREAM_*` seams; it answers only from committed captures (plugin fixtures, P0-LIVE captures).
- Browser logins run through a fake `xdg-open` first on `PATH` (`tests/support/e2e/fake-browser.ts`); the paste-code
  login reads `code#state` from stdin.
- Clients: `@anthropic-ai/sdk` 0.133.0, `@google/genai` 2.28.0, `openai` 7.32.0, plus raw HTTP for the byte framing.

Measured client behaviour (the open questions of plan §2.1): `@google/genai` 2.28.0 sends the model segment raw
(`/v1beta/models/antigravity/gemini-3.6-flash-low:generateContent`), the key in `x-goog-api-key`, and `?alt=sse` for
streams; `@anthropic-ai/sdk` sends `x-api-key` and `anthropic-version: 2023-06-01`; `openai` sends `Authorization: Bearer`.
