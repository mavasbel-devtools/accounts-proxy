## 3. E2: native streaming captures

**Scenarios, per target T1–T3:**
- S1 plain text: "Reply with the single word OK."
- S2 tool loop: one tool `get_time(timezone)`; the model calls it; a second request sends the tool result; final text.
- S3 thinking: Claude `thinking` at the minimum budget the model accepts; Gemini `thinkingConfig` = catalog-exact value (law §0.1).

This is 4 requests per target, 12 in total.

**What is recorded for each exchange:**
- the outbound request: method, URL, headers, body;
- every response chunk with a monotonic timestamp, which proves incremental streaming;
- status and response headers.

**Redaction**, done before anything is written:
- `authorization` header;
- access/refresh tokens;
- email;
- project id;
- device/session ids;
- `metadata.user_id`.

Each is replaced by a fixed placeholder. A secret scan then runs over the output (the token prefixes `sk-ant-`, `ya29.`, `1//`, plus the account's own values, held in memory only); any hit aborts the write.

**Output:**
- `tests/fixtures/captures/p0-live/<target>-<scenario>.json`;
- `docs/reference/<ts>-p0-live-e2-captures.md`, with the table of exchanges, statuses, time to first byte and chunk counts.

## 4. E3: fidelity matrix

Every probe is the minimal native request for its upstream: Anthropic fields for T1, Gemini fields inside the Antigravity envelope for T2–T4. They go through the provider package's own session and transport, so auth, headers and envelope are the production ones. Probes use `max_tokens`/`maxOutputTokens` ≤ 32 (thinking probes: the model's minimum budget).

| # | Feature | Probe | Observable proof of acceptance |
|---|---|---|---|
| F1 | image input | 8×8 PNG, single colour, "what colour?" | 200 and the colour named |
| F2 | document input | 1-page PDF containing a code word | 200 and the code word returned |
| F3a–d | tool_choice auto / any (required) / none / specific tool | one tool | call made or not as each mode requires |
| F4 | parallel tool calls | two independent tools, "call both" | two calls in one turn |
| F5 | thinking + signature replay | thinking turn with a tool call, then replay of the signed block | 200 on replay; thought/signature present |
| F6 | stop sequences | "count 1 to 10", stop at "5" | output stops before "5"; finish reason = stop sequence |
| F7a–c | temperature / top_p / top_k | each set alone | 200, or the exact 400 message |
| F8 | system placement | system prompt "always answer BANANA" | 200 and BANANA |
| F9 | cache_control (T1) / no equivalent (T2–T4) | an `ephemeral` block | 200; cache usage fields recorded |

**Classification of each cell**, with the evidence (status, error text, the observed output):
- ACCEPTED: 200 and the effect is observed;
- IGNORED: 200 but no effect;
- REJECTED: 4xx.

There is no UNVERIFIED value: a probe that cannot run is re-run, or reported as blocked with the reason.

**Volume:** about 17 probes × 4 targets ≈ 68 requests.
- Sequential, 2 s apart.
- The first 429 or `RESOURCE_EXHAUSTED` **stops the run** and is reported with its `retry-after`. There is no rotation (D4) and no retry loop.
- Antigravity quota is read before and after with `quota antigravity`, and the difference is recorded.

**Output:** `docs/reference/<ts>-fidelity-matrix.md`. It is the only source for the FeatureSupport tables (P5) and must have no UNVERIFIED cell for the two native cells (T1 Anthropic, T2/T3 Gemini).

## 5. E4: refresh-token rotation (runs last; can cost one re-login)

**Steps, per provider, on the router's own fresh account only** (never Claude Code's or the plugins' files; the store path is checked before the run):
1. Read the stored refresh token R0 (in memory only).
2. Force one refresh, giving R1, persisted through the normal session path.
3. Record whether R1 ≠ R0 (rotation).
4. If it rotated, call the token endpoint once with R0. Record the status and error code (`invalid_grant` or success).
5. Call the token endpoint once with R1. This shows whether reusing R0 revoked the whole token family (reuse detection).

**Risk:** reuse detection can revoke R1 too. **Rollback:** run `login <provider>` again. Nothing else depends on these accounts.

**Output:** `docs/reference/<ts>-e4-refresh-rotation.md`, which decides D5's shared-credential mode.
